# 宣传介绍片：论证与解说词

成片：[`promo/zhidian-promo.mp4`](../promo/zhidian-promo.mp4)（1920×1080，约 3 分钟，无声，带中文字幕）。
这份文档是它的文字版：先是四个角度的论证（NABC），再是可以照着念的解说词。

同一套内容的另外两种形式：幻灯片 [`promo/zhidian-deck.pptx`](../promo/zhidian-deck.pptx)（13 页，每页带讲稿备注）和流程图动画 [`promo/zhidian-flow.mp4`](../promo/zhidian-flow.mp4)（1 分钟，Remotion）。

一句话：**让所有人都能用上更简单的 AI。** 不要求新电脑，不要求联网，不要求会写提示词；会用鼠标，就会用它。

## 为什么要做它：NABC

### N · 需求（Need）

难的不是 AI，是用上 AI 的那几步。

- **想问屏幕上的一个东西，今天要六步**：截图 → 切到聊天窗口 → 粘贴 → 琢磨提示词怎么写 → 等回答 → 再切回来。
- **要会写提示词**。说不清楚，就得不到好答案。会用的人越用越顺，不会的人被挡在门外。
- **要联网，要上传**。屏幕上的合同、报表、聊天记录，要先发到别人的服务器上。
- **要新电脑**。Windows 自带的同类功能 Click to Do 要求 Copilot+ PC：40 TOPS 的 NPU、16 GB 内存、8 个逻辑处理器。[^ctd]
- 而办公室里最常见的需求其实很朴素："把这几个文件合成一个 PDF""这段话帮我排一下版"。这些事不需要一个会聊天的模型，需要的是**不用学就会用的入口**。

### A · 方法（Approach）

把 AI 装进每个人都会用的东西：鼠标指针。

- **指着问**。按热键，鼠标停在哪，对话框就出现在哪；右键固定，左键点一个选项或者直接打字。回答之后，AI 用它自己的光标在屏幕上指出"就是这里"。
- **选中就办**。选中文件或文字，鼠标旁边就列出能做的事（合并 PDF、做成 PPT、Word 一键排版、转格式、文字自动排版……），点一下就做完，结果放在原文件旁边，原文件不动。
- **底下**：一个 0.8B 的本地视觉模型（Qwen3.5，量化后 0.74 GB，llama.cpp），加上我们自己训练的 LoRA 指针适配器（12.8 MB），纯 CPU、离线。办公动作不经过模型，是确定的本地程序：做了什么、哪里没做到，如实告诉你。
- 没有任何原生模块：Windows、macOS、Linux 用的都是系统自带的接口。

### B · 收益（Benefit）

| 对用的人 | 依据 |
|---|---|
| **0 行提示词**：停住、右键、左键 | 交互设计；Linux 上 25 步真实鼠标键盘的自动化测试 |
| **0 字节上传**：截屏、模型、文件转换都在本机，断网照常用 | 模型服务只监听 127.0.0.1，启动参数带 `--offline` |
| **普通笔记本就能跑**：模型 0.74 GB，运行时内存 1–2 GB，没有显卡 | CI 实测，Windows / Linux，4 核 CPU |
| **回答和位置一趟给出，约 7 秒**（原来要两趟、17–25 秒） | CI 第 11 次运行，同一组 8 题：7.1 秒 / 6.6 秒 对 24.8 秒 / 16.8 秒 |
| **指得准**：训练中没见过的界面类型上，指对的比例 10% → 72.5%；见过的类型 94.2% | 离线评测，各 120 条，`train/results/eval.json` |
| **33 个办公动作，一次点击，原文件不动** | 每个动作在真实应用里对真实文件执行、再打开结果核对；另有检查把全部动作在 23 种选中情况下各跑两遍，确认原文件没变、不覆盖已有文件 |

要同时说清楚的边界：在真实测试页的 8 道题里，带适配器的模型指对 4–5 题（和慢的那种办法相当，不是更准）；0.8B 是小模型，会答错；适配器的训练数据是程序合成的界面。全部数字和测法在 [`benchmarks.md`](benchmarks.md)。

### C · 竞争（Competition）

大厂也在做"AI 指针"，但都要你先换点什么。

| | Google Magic Pointer | Windows Click to Do | 聊天框式 AI 助手 | **指点** |
|---|---|---|---|---|
| 需要的电脑 | Googlebook | Copilot+ PC（40 TOPS NPU、16 GB 内存）[^ctd] | 不限，但要联网和账号 | **普通笔记本，纯 CPU** |
| 内容去哪里 | 识别在本机，回答和动作交给 Gemini（云端）[^mp] | 屏幕分析和几项文字动作在本机；文字动作会把选中的文字发到云端做安全检查，搜索、问 Copilot 时联网[^ctd] | 上传到云端 | **默认不出本机** |
| 怎么开口 | 晃鼠标、圈选 | 快捷键 + 点选 | 截图、粘贴、写提示词 | **停住或选中，点一下** |
| 指回屏幕 | 没有 | 没有 | 没有 | **AI 光标指给你看** |
| 文件与排版 | 交给云端模型 | 文字、图片的若干动作 | 靠对话来回试 | **确定的本地工具，不改原文件** |

要说准确：Google 和微软都有在本机运行的部分，不能说它们"没有本地版本"。差别在于它们要特定的新电脑，而且一到真正回答或执行动作就要联网或过一道云端检查；指点默认整条链路都在一台普通电脑上。

我们的取舍：不要求新电脑，不要求联网，不要求会写提示词。代价也要说：模型小，能力有限；目前是黑客松原型，没有人在真实的笔记本上长期用过。

[^ctd]: Microsoft 支持文档 "Click to Do: do more with what's on your screen"，硬件要求和隐私说明（2026 年 11 月查阅；其中"文字动作会把选中的文字发到云端做安全检查"一条取自搜索结果对该页的引述，没有打开原页面逐字核对）：<https://support.microsoft.com/windows/ai/ai-features/click-to-do-do-more-with-what-s-on-your-screen>
[^mp]: 公开报道，说法不完全一致：识别"指着什么"在本机，执行动作时把内容交给云端的 Gemini。见 Android Authority <https://www.androidauthority.com/googlebook-magic-pointer-local-cloud-processing-3715403/> 和 BGR <https://bgr.com/2173683/google-magic-pointer-frustrating-trend/>（2026 年 11 月查阅）。

## 片子是怎么做的（保证画面是真的）

- **录屏是真实应用**：`promo/record.mjs` 在虚拟桌面上启动真实的「指点」，用真实的鼠标键盘事件操作，ffmpeg 抓屏。
- **回答是回放**：制作片子的机器跑不了模型，所以"指着问"里的回答、坐标和耗时取自 CI 上带适配器模型的真实运行记录（`promo/recording.json`，由 `promo/make-recording.py` 从 CI 日志生成），界面上和字幕里都标着"回放"。片中选的是那次运行里答对并指对的两题；同一次运行里它也有答错的题，见 `benchmarks.md` 3.2 节。
- **办公动作是真的执行**：合并出的 PDF、做出的 PPT、排版后的 Word 都是录制时生成的文件。Linux 的文件管理器没有读取选中项的接口，所以片中的文件夹是示意界面，选中的文件由脚本送入应用（Windows 上这一步由读取资源管理器的助手完成，已在 CI 上对着真实的资源管理器窗口验证）。
- **等待处有快进**，画面右上角有标注；回答流出的过程是原速。
- 合成：`promo/film.html` 是按时间轴定位的页面，`promo/render.mjs` 逐帧截图交给 ffmpeg 编码。重新生成：

```bash
xvfb-run -a -s "-screen 0 1282x800x24" node promo/record.mjs ask
xvfb-run -a -s "-screen 0 1282x800x24" node promo/record.mjs act
node promo/render.mjs
```

## 幻灯片和流程图动画

- **幻灯片**由 [`promo/make-deck.mjs`](../promo/make-deck.mjs) 用 PptxGenJS 生成（和应用里"做成 PPT"用的是同一个库）：封面、问题、N、A（两页演示截图加一页真实产出）、底层原理、B、LoRA 的数字、C、验证到了什么程度、结尾。数字和这份文档、[`benchmarks.md`](benchmarks.md) 一致；改了数字要两边一起改。重新生成：`node promo/make-deck.mjs`。
- **流程图动画**是 [`promo/flow/`](../promo/flow/) 里的一个 Remotion 工程（React 组件按帧号算出画面）。内容：「指着问」七步（热键 → 截一帧 → 本地吸附 → 右键固定 → 本机模型 → 回答加坐标 → AI 光标）、「选中就办」五步（选中 → 读出选中项 → 面板列出动作 → 本机转换 → 新文件），每一步标明是谁做的（你 / 本机程序 / 本机模型），最后两条线一起放进"你的电脑"的边界里，外面是被划掉的云。重新生成：

```bash
cd promo/flow
npm install
npm run render        # 输出 promo/zhidian-flow.mp4
npm run studio        # 在浏览器里逐帧预览和修改
```
